# 완료 판정 및 테스트 케이스

## 1.6.3: 전체 라이브러리와 BookOrbit 명칭

기능 테스트는 로컬 JVM 단위 테스트 48개다. 이전 APK 빌드 요청을 이어 Debug/Release 빌드 및 정적 서명 검사를 수행했다. 실제 기기·에뮬레이터·실서버 검증을 의미하지 않는다.

- [x] 설정에서 기본 라이브러리 선택/적용을 제거하고 연결 확인 성공 시 전체 라이브러리를 자동 적용함
- [x] 인기는 모든 라이브러리의 만화를 표시하고, 필터 기본값도 전체 라이브러리임
- [x] 특정 라이브러리를 고르면 해당 라이브러리만 탐색·검색하며 저장된 작품 연결을 변경하지 않음
- [x] 라이브러리 간 동일 seriesId 보존, 40작품 페이지 경계, 빈 라이브러리, hasNextPage, 오류·재시도·TTL 격리 검증
- [x] 앱 표시명 BookOrbit, 소스명 BookOrbit I / II / III, 기존 소스 ID 유지
- [x] 이전 단일 라이브러리 설정의 작품 binding과 인증된 이미지 연결 유지
- [x] 접근 가능한 라이브러리가 0개인 계정은 빈 결과이며 과거 접근 권한이 재활성화되지 않음
- [x] 로컬 JVM 단위 테스트 48개 통과, LiveServerTest 기본 제외
- [x] Debug/Release APK 빌드 및 Manifest·서명 검사 통과
- [x] v1.6.3 Release 및 Mihon Pages 스토어 배포, 공개 JSON/APK HTTP 200과 바이트·체크섬 일치
- [x] 사용자가 1.6.3의 정상 동작을 확인했다고 보고함 (세부 환경/시험 항목 미제공)
- [ ] 에이전트의 실제 Mihon 설치·신뢰 승인·UI·읽기 자동 재검증 — 미실행

## 과거 1.6.2: 3개 소스와 라이브러리 필터

이번 변경의 기능 테스트는 **로컬 JVM 단위 테스트만** 실행했다. 후속 APK 빌드 요청으로 Debug/Release 빌드와 정적 서명 검사를 추가했다. 합성 응답을 실제 서버 검증으로 취급하지 않는다. 상세 실행 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.

- [x] 소스 팩토리는 고정 3개를 반환하며 슬롯 1~3의 기존 ID를 유지함 (코드 검토/ID 단위 테스트)
- [x] 최신을 비활성화하고 비어 있지 않은 라이브러리 필터 목록을 제공함 (공식 호스트 코드 대조/컴파일)
- [x] 필터와 검색어가 선택한 라이브러리 ID의 목록 API에 적용됨 (합성 TLS 응답 단위 테스트)
- [x] 필터/기본 라이브러리 변경 뒤 기존 작품·챕터·이미지는 원래 연결을 유지함 (단위 테스트)
- [x] 이름 변경·재정렬·키 회전 뒤 선택 의미와 binding을 유지함 (단위 테스트)
- [x] 다른 서버·계정 또는 삭제된 라이브러리의 과거 필터/작품/이미지를 잘못 연결하지 않음 (단위 테스트)
- [x] 구형 단일 라이브러리 설정을 읽고 기존 binding을 유지하여 레지스트리를 확장함 (단위 테스트)
- [x] `LiveServerTest`는 기본 단위 테스트 작업에서 제외됨
- [ ] 변경된 UI를 실제 Mihon에서 확인 — 사용자 요청에 따라 미실행
- [x] 변경된 소스로 Debug/Release APK 빌드 및 정적 Manifest·서명 검사 — 후속 사용자 요청으로 실행
- [ ] 변경된 APK 설치·신뢰 승인·실제 탐색/읽기 — 미실행

슬롯 4~6의 기존 저장 작품은 자동 이관되지 않는다. 연결 적용 후 소스 화면 재진입이 필요하다. 배포된 1.6.1 APK와 스토어 피드는 이번 소스 변경을 포함하지 않는다.
